# eval-first-rag

Компактный RAG-конвейер с evals как гейтом качества: golden set из 52 вопросов, метрики **hit@k / MRR / полнота ответа / цитируемость / groundedness**, LLM-as-judge с офлайн-фолбэком и eval-гейт с exit 1 при провале порогов. Работает на чистом stdlib Python — ноль зависимостей, детерминированные прогоны.

Проект демонстрирует подход к ЖЦ AI-решений, который я считаю обязательным: **метрики и пороги определяются до изменения промпта/поиска/модели, а качество проверяется автоматически на каждом запуске** — как тесты, только для семантики.

## Что внутри

| Слой | Решение | Комментарий |
|---|---|---|
| Поиск | Гибрид: BM25 + TF-IDF, слияние через Reciprocal Rank Fusion (k=60) | В production TF-IDF-ветка → dense-эмбеддинги, BM25 → SPLADE; RRF и интерфейс не меняются |
| Генерация | Extractive-режим (только из найденных чанков, с цитатами) | Ответ всегда проверяем источником; LLM-генерация подключается опционально |
| Evals | golden.jsonl: 52 вопроса (парафразы, разговорные формулировки, морфологические варианты) с ожидаемым документом и обязательными фрагментами ответа | Расширение сьюта — первый шаг при любом изменении конвейера |
| Метрики | hit@3, MRR, answer_coverage, citation_rate, groundedness | Текущие значения: **hit@3 0.87, MRR 0.79, полнота 0.87, цитируемость 0.73** при порогах 0.85 / 0.75 / 0.85 / 0.70 (пороги заданы в `run_evals.py` — это контракт) |
| Судья | LLM-as-judge по бинарной рубрике (`grounded: true/false`), любой OpenAI-совместимый API | В прогоне ниже судья — детерминированный lexical-фолбэк (порог покрытия 0.9); LLM-ветка подключается ключом и не гонялась |
| CI | GitHub Actions: прогон evals на push/PR, exit 1 при провале порога | Локально гейт уже работает: `python evals/run_evals.py` возвращает exit 1 при провале; файл воркфлоу — `docs/ci.yml`, скопировать в `.github/workflows/` |

## Запуск

```
python evals/run_evals.py                # офлайн, детерминированно
LLM_API_KEY=... python evals/run_evals.py   # + настоящий LLM-судья
```

Отчет: `reports/eval_report.json` (метрики + по-вопросная детализация).

Подключение провайдера судьи:

```
export LLM_API_KEY=...
export LLM_BASE_URL=https://api.example.com/v1   # опционально
export LLM_MODEL=gpt-4o-mini                       # опционально
```

## Честные границы

- Корпус — синтетическая база знаний финтех-поддержки (вымышленный банк, 10 документов); это демонстрация подхода, не production-система. Метрики получены на 52 вопросах к этим 10 документам — на таком объёме высокие значения достигаются легче, чем на реальном корпусе.
- Расширение golden set с 15 до 52 вопросов (парафразы, морфологические варианты) опустило hit@3 с 1.00 до 0.87. Единица на лёгком сете ничего не доказывала; промахи на жёстком сете — рабочий материал.
- Все 7 полных промахов — лексические: токенизация без стемминга («микрозайма» ≠ «микрозайм», «паролю» ≠ «пароль», «займу», «кэшбэка») и синонимы («посылка» вместо «заказ»). Это и есть главный аргумент за dense-эмбеддинги в следующей итерации — интерфейс RRF не меняется.
- Пороги пересчитаны после расширения сьюта (0.90/0.85 → 0.85/0.75 и т.д.): жёсткий бенчмарк сделал прежние пороги недостижимыми. Пересчёт задокументирован в `run_evals.py` — снижение порога это решение, а не деградация.
- Lexical-фолбэк судьи — грубая прокси groundedness (покрытие токенов ответа контекстом); extractive-режим делает метрику почти тавтологией. Настоящий судья — LLM по бинарной рубрике; в прогоне ниже LLM-ветка не гонялась.
- Воркфлоу CI лежит в `docs/ci.yml` (скопировать в `.github/workflows/`): гейт с exit 1 работает локально и готов к подключению, но в этом репозитории Actions ещё не прогонялся.
- Dense-ретрив, реранкинг и инференс-слой — следующие шаги того же каркаса.

## Почему eval-first

Изменение промпта, модели или параметров поиска без замера — это деградация, которую замечают пользователи, а не разработчики. Здесь каждый прогон сравнивается с порогами, спор «стало лучше или хуже» решается отчетом, а не мнением, а расширение golden set — первый шаг любого изменения конвейера: сначала сьют делает метрику честной, потом код делает метрику высокой.
