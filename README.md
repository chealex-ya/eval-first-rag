# eval-first-rag

Компактный RAG-конвейер с evals как гейтом качества: golden set, метрики **hit@k / MRR / полнота ответа / цитируемость / groundedness**, LLM-as-judge с офлайн-фолбэком и eval-гейт в CI. Работает на чистом stdlib Python — ноль зависимостей, детерминированные прогоны.

Проект демонстрирует подход к ЖЦ AI-решений, который я считаю обязательным: **метрики и пороги определяются до изменения промпта/поиска/модели, а качество проверяется автоматически на каждом коммите** — как тесты, только для семантики.

## Что внутри

| Слой | Решение | Комментарий |
|---|---|---|
| Поиск | Гибрид: BM25 + TF-IDF, слияние через Reciprocal Rank Fusion (k=60) | В production TF-IDF-ветка → dense-эмбеддинги, BM25 → SPLADE; RRF и интерфейс не меняются |
| Генерация | Extractive-режим (только из найденных чанков, с цитатами) | Ответ всегда проверяем источником; LLM-генерация подключается опционально |
| Evals | golden.jsonl: 15 вопросов с ожидаемым документом и обязательными фрагментами ответа | Расширение сьюта — первый шаг при любом изменении конвейера |
| Метрики | hit@3, MRR, answer_coverage, citation_rate, groundedness | Пороги заданы в `run_evals.py` — это контракт |
| Судья | LLM-as-judge по бинарной рубрике (`grounded: true/false`), любой OpenAI-совместимый API | Без ключа — детерминированный lexical-фолбэк (порог покрытия 0.9) |
| CI | GitHub Actions: прогон evals на push/PR, exit 1 при провале порога | Eval-гейт как условие мержа; файл воркфлоу — `docs/ci.yml` (скопировать в `.github/workflows/`) |

## Запуск

```
python evals/run_evals.py                # офлайн, детерминированно
LLM_API_KEY=... python evals/run_evals.py   # + настоящий LLM-судья
```

Отчет: `reports/eval_report.json` (метрики + по-вопросная детализация).

Подключение провайдера судьи:

```
export LLM_API_KEY=...
export LLM_BASE_URL=https://api.example.com/v1   # опционально
export LLM_MODEL=gpt-4o-mini                       # опционально
```

## Честные границы

- Корпус — синтетическая база знаний финтех-поддержки (вымышленный банк, 10 документов); это демонстрация подхода, не production-система.
- Lexical-фолбэк судьи — грубая прокси groundedness (покрытие токенов ответа контекстом); настоящий судья — LLM по бинарной рубрике.
- Dense-ретрив, реранкинг и инференс-слой — следующие шаги того же каркаса.

## Почему eval-first

Изменение промпта, модели или параметров поиска без замера — это деградация, которую замечают пользователи, а не разработчики. Здесь каждый прогон сравнивается с порогами, CI блокирует регрессию, а спор «стало лучше или хуже» решается отчетом, а не мнением.
